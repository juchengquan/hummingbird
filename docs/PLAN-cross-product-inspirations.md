Generated by a five-agent fan-out across these cohorts:

1. **Power-user AI chat clients** — Open WebUI, LibreChat, T3 Chat, Big-AGI, Msty, Claude.ai / ChatGPT Projects.

## Executive summary

Three items rise to the top across all five cohorts:

1. **Workspace-level system prompt that layers under the agent persona** (Claude / ChatGPT Projects pattern). Smallest delta, fills a real gap in the workspaces slice, lays the groundwork for everything below. Days, not weeks.
2. **Letta-style three-tier self-editing memory** (closes the cross-conversation memory plan with a *known-working* contract rather than reinventing). The "agent edits its own memory via `core_memory_*` and `archival_memory_*` tools" shape is the part that makes it work in practice — pure embed-on-write degrades fast. Maps cleanly onto Supabase pgvector that's already wired for `searchFiles`.
3. **Langfuse self-hosted for tracing + prompt management + LLM-as-judge evals across all three backends.** Single Docker stack covers cost visibility, distributed-trace debugging across Next.js + agent-py + agent-ts, and a regression net before every Anthropic model swap. Highest leverage per unit of infra.

A fourth standout if a more differentiated UX is the goal: **Msty Flowchat-style canvas-of-branches** — wire conversation forks to land as nodes on the existing workspace canvas. Pure composition of two surfaces Hummingbird already has; no other chat client in the cohort ships this.

## By cohort

### Power-user chat clients
- **Msty Flowchat** — canvas-of-branches; every regenerate/branch is a node on a pan/zoom canvas. Hummingbird has both react-flow canvas + `forkConversation`; this is one composition. Source: [msty.ai/blog/msty-1.1](https://msty.ai/blog/msty-1.1)
- **Big-AGI Beam** — scatter prompt to N models, gather, optionally fuse into one answer. The UX that BYO-model uniquely unlocks; nobody else in the cohort copies it well. Source: [big-agi.com/blog/release-1.15.0-beam](https://big-agi.com/blog/release-1.15.0-beam)
- **Claude / ChatGPT Projects** — project-level custom instructions that stack on the account-level prompt, don't eat context budget. Hummingbird has workspaces and per-agent personas, but no layered workspace-system-prompt today. Source: [Anthropic docs](https://support.claude.com/en/articles/9519177-how-can-i-create-and-manage-projects)
- **Open WebUI #-mention for Knowledge collections** — autocomplete over collections + a per-attach toggle for "full context" vs "RAG retrieval." The retrieval-mode toggle is the missing knob for large files. Source: [docs.openwebui.com/features/workspace/knowledge](https://docs.openwebui.com/features/workspace/knowledge/)
- **LibreChat three-mode forking** — visible-only / related-branches / include-branches when forking. Hummingbird already has fork; this is a UI upgrade. Source: [librechat.ai/docs/features/fork](https://www.librechat.ai/docs/features/fork)

### Agent observability + cost-control
- **Langfuse self-host** — OTLP ingest works for all three backends with no bespoke wiring; prompt versioning with strong client+server caching; datasets + LLM-as-judge evals on production traces. EE-license gates RBAC / audit logs / SSO but org-level RBAC is free. Source: [langfuse.com/docs](https://langfuse.com/docs)
- **LiteLLM virtual keys + budgets** — `/key/generate` mints scoped keys with RPM/TPM caps and monthly spend ceilings. Maps onto Hummingbird's per-IP buckets and would let workspaces (not just IPs) get dollar quotas. Source: [docs.litellm.ai/docs/proxy/virtual_keys](https://docs.litellm.ai/docs/proxy/virtual_keys)
- **Vercel AI Gateway `caching: 'auto'`** — one-flag change to start cashing Anthropic prompt-cache hits without rewriting calls; tagged dashboard becomes a per-workspace cost view if Hummingbird adds `workspace_id` as a request property. Source: [vercel.com/docs/ai-gateway/models-and-providers/automatic-caching](https://vercel.com/docs/ai-gateway/models-and-providers/automatic-caching)
- **Phoenix prompt playground** — replay any captured trace against alternate prompts/models side-by-side, locally. Useful as a dev-loop "diff this skill prompt against Sonnet vs Opus" UI before any model swap.

### Agent orchestration + long-term memory
- **Letta three-tier self-editing memory** — Core (always in context, agent edits via `core_memory_append`/`replace`), Recall (searchable convo history), Archival (pgvector long-term, `archival_memory_*` tools). The tool-driven self-edit is the part embed-on-write retrieval misses. Self-hostable via Docker Compose with bundled Postgres+pgvector. Source: [letta.com/blog/memory-blocks](https://www.letta.com/blog/memory-blocks)
- **LangGraph checkpointer + interrupts** — `interrupt(payload)` pauses a graph mid-node and serialises the stack; resume from any prior checkpoint. Hummingbird's `RunStore` already appends idempotently on `(task_id, seq)` — one step from a real checkpointer. Would make HITL approvals durable across restarts. Source: [docs.langchain.com/oss/python/langgraph/interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)
- **OpenAI Agents SDK handoffs-as-tool-calls** — an agent calls `transfer_to_X()` and the runtime swaps context. Trivially portable to Hummingbird's Anthropic tool loop: one new tool + one `currentAgent` slice field. Needs a depth cap to avoid Swarm-style symmetric-handoff loops.
- **Mastra evals as first-class primitives** — model-graded + rule-based + statistical evals adjacent to agents in the same TS codebase. Closes the "agent eval" gap on agent-ts without a separate framework.

### Code + research workflows
- **Elicit structured extraction tables** — pull `sample_size / intervention / outcome` across N papers into a sortable grid, each cell quote-cited. The killer artifact for Deep Research output — turns prose into a reusable, citation-cell dossier the user can edit in the Plate panel. Source: [elicit.com/blog/systematic-review](https://elicit.com/blog/systematic-review/)
- **Aider architect/editor pair** — strong planner emits a plan; cheap fast model emits diffs in search/replace blocks. Pattern: cheaper + more reliable Plate.js AI edits via structured patches with diff preview. Source: [aider.chat/docs/usage/modes](https://aider.chat/docs/usage/modes.html)
- **Cursor `@Docs` + scoped MDC rules** — bundle URL bookmarks/files/notes into named, composable context handles that auto-attach per-glob. Natural extension of Hummingbird's URL bookmarks + workspace personas.
- **Continue context providers as plugins** — `@codebase`, `@docs`, `@terminal` as typed providers in the chat input. Hummingbird's skills already are typed providers — promote them to `@`-mentions with the same UX.
- **Perplexity Spaces focus modes** — Academic / YouTube / Reddit toggles restrict source type. Deep Research could expose "Academic only", "Docs only", "Bookmarks only" toggles trivially.

### Self-host infra + local inference
- **Ollama as a fourth provider branch** in `lib/server/model-provider.ts`. Copy the Minimax custom-base-URL pattern. Unlocks zero-cost local chat + structured outputs + embeddings via OpenAI-compatible endpoints. The cleanest single change in the whole survey. Source: [docs.ollama.com/api/openai-compatibility](https://docs.ollama.com/api/openai-compatibility)
- **OpenRouter as a fifth provider branch** with `openrouter/auto` as a model option + per-request `models: [...]` fallback list. Buys routing, fallback, and free prompt caching for no infra. Source: [openrouter.ai/docs/guides/routing/routers/auto-router](https://openrouter.ai/docs/guides/routing/routers/auto-router)
- **Hybrid search in `searchFiles`** — add a pgvector column to `file_sections`, populate via Ollama embeddings (self-host) or a small hosted embedder, blend with the existing FTS via LlamaIndex's alpha-tuning pattern. Contract `searchFiles` exposes doesn't change.
- **transformers.js client-side embeddings** — `all-MiniLM-L6-v2` (~23 MB) via WebGPU, 8–12 ms per chunk on M2. Embed pasted text/uploaded files in the browser before they hit the server — zero-cost privacy win for the "Stay local-first" constraint.

## Skip list

- **Open WebUI Channels** (multi-user shared rooms with `@`-tagged models). Premature — needs the multi-tenant story first (RBAC, sharing, billing). Promote back when "multi-tenant workspaces" stops being out of scope.
- **CrewAI hierarchical delegation** with `allow_delegation=True` between peers. Documented "Delegation Ping-Pong" OOM crash mode where two agents bounce a task until process death. The role/goal/backstory *prompt shape* is fine to borrow into custom agents; the autonomous delegation loop is not.
- **AutoGen Studio** as a runtime dep. Explicitly "not production-ready"; Microsoft is steering users to Agent Framework. The `SelectorGroupChat` pattern is borrowable but the framework itself isn't a fit.
- **Helicone** as a runtime dep. Acquired by Mintlify 2026-03-03; maintenance-mode, no roadmap. Borrow the `Helicone-Property-*` custom-property header pattern (trivial to bolt onto the AI Gateway call site) but don't take a code dependency.
- **vLLM as a first-class integration**. Worth using as a target *behind* the OpenAI-compatible adapter (same code path as Ollama, different base URL) for users who run their own GPU. Not worth Hummingbird owning a vLLM deployment story.
- **Mem.ai-style "AI auto-linking / auto-tagging" as a headline feature**. Reviewers consistently report search misses and the linker is inconsistent enough that power users fall back to manual tags. The retrieval quality (FTS + reranker, eventually + vectors) is the actual product; "AI links your notes" is a thin marketing surface that ages poorly.
- **Browser-extension companion**. Chrome Web Store ops + cross-browser maintenance is a substantial side-business; not worth it unless a clear power-user demand emerges.

## Open questions

1. **Multi-tenant trajectory.** Several patterns (Open WebUI Channels, Claude Projects sharing, LiteLLM virtual keys per workspace) only make sense once Hummingbird has a multi-tenant story. Today it's per-user. Is multi-tenant on the 6-month horizon? If yes, items 4 + 10 want to bake in `workspace_id` tagging now to avoid migration pain. **Partially de-risked:** item #4 Part 2 already tags every `/api/chat` Gateway call with `workspace:<id>`, so the per-workspace cost/latency cut exists today; item #10 (Langfuse) should reuse the same `workspaceId` attribute when it lands.
2. **Eval investment.** Item 10 (Langfuse) is high-leverage only if the team commits to actually writing evals. A trace/cost dashboard with no eval suite is a measurable productivity-loss (everyone alt-tabs to it, nobody acts on it). Are we ready to allocate the few-days/week of eval writing this needs?
3. **Memory editor surface.** Item 13 (Letta-style memory) introduces *agent-editable persistent state*. The product question that needs an answer before building: do users see and edit their memory blocks directly (Letta's choice — the agent edits a visible string), or is it hidden behind the chat (ChatGPT's "Memory" feature surface)? The visible-block approach is more trustworthy but adds UI surface; the hidden approach is sleeker but corrodes trust fast when the agent remembers something the user doesn't recall telling it. Pick before coding.

## Verification notes

Flagged during research, repeated here so they're easy to find:

- **Helicone** is in maintenance mode since 2026-03-03 (acquired by Mintlify). Don't take a code dep; borrow patterns only.
- **AutoGen** in maintenance, steered to Microsoft Agent Framework. AutoGen Studio explicitly "not production-ready."
- **T3 Chat "2× faster than ChatGPT / 10× faster than DeepSeek"** appears in third-party blogs only; not in Theo's own materials. Treat as positioning, not spec.
- **LibreChat "Dynamic Context / intelligent context compression"** is on the 2026-02 roadmap blog, not in shipped features. Roadmap, not shipped.
- **Msty "Context Shield"** name appears in third-party reviews but I couldn't verify it on docs.msty.app. Treat the specific name as unverified.
- **Langfuse self-host caveats**: project-level RBAC, audit logs, retention policies, SSO enforcement, SCIM all require an EE license key even when self-hosted. Org-level RBAC and basic SSO are free.
- **LiteLLM self-host caveats**: admin UI, Prometheus metrics, SSO for >5 users, JWT auth, guardrails are all Enterprise-only.
- **PGlite reality check**: viable browser-side vector search up to ~5–10k chunks per published browser-RAG writeups; past that, fall back to server Postgres.
- **CrewAI delegation ping-pong** is a documented OOM crash mode, not a hypothetical.
